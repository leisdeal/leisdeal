## 1. 背景与核心判断

Leisdeal 直播涉及美国仓、TikTok Shop 履约、FBT、IOR、FDA、VOSB/SAM、政府采购、产品合规等高风险话题。主播需同场处理：评论问题、合规边界、线索判断、私信引导、散场复盘。

V1 不做完整自动化系统，只做一条最小可用链路：

> 评论进入 → FAQ / 红线命中 → 中控屏出卡片 → 人工决定是否上播 → 散场复盘。

V1 核心价值**不是** AI 实时生成回答，而是：① 红线拦截 ② 标准答案命中 ③ 高频问题识别 ④ 线索捕获 ⑤ 直播复盘。生成式回答只作长尾辅助，只给中控看，不直接上播。

---

## 2. 平台判断（V1 = 抖音）

- **TikTok US**：官方仅 Research API 的**视频**评论查询，非 LIVE 全量弹幕；Shop API 覆盖目录/订单/发货/付款，非评论流；TikTok-Live-Connector 等为 unofficial / 逆向路线，不作 V1 生产主路径。→ 不作 V1 平台。
- **抖音**：开放平台「直播间评论互动能力」只给挂载弹幕小玩法后**命中特殊指令**的评论，非全量。全量只能走本机直播伴侣本地链路 PoC，需单评 ToS/稳定性/重连/延迟。

**锁定**：V1 只验证「自己直播间 + 自己机器 + 直播伴侣本地链路」，不抓他人直播间，不做公开数据采集产品。

---

## 3. 用户角色

- **主播**：直播表达，不操作系统。
- **中控**（Daniel 或指定助理）：盯 Copilot 屏；判断哪些问题提醒主播；对 L3 拦截；标记线索；记录主播实际回答效果。
- **Lei**：审核 FAQ 标准答案与红线清单；决定哪些话术可上播；据复盘调策略。
- **开发**：ingestion / 检索 / 红线 / 中控 UI / 日志复盘 / eval。

## 4. 数据来源

**评论来源（优先级）**：① Week 0 直播伴侣本地 PoC → ② PoC 失败：人工副屏复制评论进输入框（下游链路不变）→ ③ PoC 成功：接本地 WebSocket 流。

**FAQ 来源**：必须 Lei 提供/审核。最小启动集 100 条，每条含标准答案、L1/L2/L3、禁止说法、是否可直播回答、是否必须引导私信。

**测试集**：至少一场真实直播——评论记录 + 主播实际回答 + 当时哪些评论有效 + 哪些应红线拦截 + 哪些应引导私信。

## 5. 风险分级

| 级别 | 定义 | 典型 | 处理 |
| --- | --- | --- | --- |
| **L1** 低 | 可直播回答 | 仓库在哪、发货流程、FBT vs 自发货、价格表怎么拿 | 直接显示标准答案卡 |
| **L2** 中 | 可答但须带边界 | FDA 产品能不能做、FBT 一定更便宜吗、退货赔付、能不能帮申请 TikTok 店 | 标准答案 + 边界提醒 + 禁止说法 |
| **L3** 高 | 不建议直播回答 | 能不能做 IOR/包清关/少报关税/包过 FDA/负责全部进口责任、VOSB 是否一定中标、Customs Bond 谁担、税务、产品出问题谁负责、能不能保证店铺通过 | **弹红卡**，不展开，引导私信 |

L3 标准红卡话术：「这个问题涉及主体、产品、文件和责任边界，不适合直播间直接承诺。你可以私信我们，我们根据具体情况做路径判断。」

## 7. 系统模块与验收标准

### 7.1 Ingestion Spike（Week 0，Gate 1）
验证直播伴侣本地链路稳定取评论。
**验收**：① 跑完一整场 ≥2 小时不掉链；② 弹幕→入库 P95 <500ms；③ 弹幕→中控屏卡片端到端 P95 <1s；④ 断线重连 ≤5s；系统尽力缓存并恢复，不可恢复的断线窗口须在复盘中标记为数据缺口（不假设断链期历史消息可追回）；⑤ 重复率 ≤3%；⑥ 丢失率用人工副屏抽样估算；⑦ 不抓非本人直播间。 `[冻结折入 #2]`
**失败降级 = 正式 V1 路径**：若 Ingestion Gate No-Go，V1 仍作为「人工输入版 Copilot」正式上线——人工副屏复制评论 → 输入框 → 同样进 FAQ/红线/复盘链路。抓包失败 ≠ 项目失败。 `[冻结折入 #4]`

### 7.2 评论清洗
去 emoji 噪音、去重、去无意义、合并相似问、标高频词。
**验收**：同类聚合；重复刷屏不反复弹卡；关键合规词不被误删。

### 7.3 FAQ 检索
SQLite 存结构化 FAQ + 向量库语义检索 + 高风险词 keyword boost。
**验收**：① eval 集 top-1 命中 ≥85%；② L1/L2 响应 P95 <300ms；③ 相似问法命中同一 FAQ；④ 不命中进 unknown，不硬凑。

### 7.4 L3 红线识别（优先级高于普通 FAQ）
三层：**规则层（关键词/正则，高 recall）→ embedding 语义 → Haiku 分类兜底**。安全关键路径不单靠 LLM。
示例触发词：包清关、包 FDA、包过、关税少报、IOR 谁负责、Customs Bond、出问题谁赔、政府采购包中、VOSB 保证拿单、税怎么避。
**验收**：① 红线召回 ≥98%（漏拦记致命失败）；② 误报不设 Go/No-Go 硬门槛，但设操作上限——L3 红卡占本场总评论 >15%（或中控反馈误报过多）即进入规则降噪优化，避免中控被红卡淹没；③ 红卡醒目，不被普通 FAQ 卡覆盖；④ L3 不显示长篇生成答案；⑤ 默认动作=引导私信/不直播展开。 `[冻结折入 #1]`

### 7.5 中控屏 UI（四区）
A 实时评论流（时间/评论/风险标签/命中状态）；B 推荐卡片（绿 L1可答 / 黄 L2带边界 / 红 L3不要直播回答 / 灰 unknown人工判断）；C 本场高频 Top10；D 线索区（找仓/要报价/要 TikTok 店/FDA/FBT/供应链合作/政府采购/想加微信）。
**验收**：① 中控 2s 内看懂卡片；② L3 红卡不得被普通卡覆盖；③ 一键标记「提醒主播/引导私信/加入复盘/加入话术库」；④ 不要求主播操作。

### 7.6 LLM 长尾辅助（不进实时主链路）
触发：FAQ 未命中 / unknown / 中控手动点「生成参考」。
限制：只给中控看；不自动上播；不自动沉淀 FAQ；须 Lei 审核后方入库；高风险不得生成承诺句。
路由：Haiku 批量归类；Sonnet 复盘与长尾参考；Opus 策略话术审核/红线升级。模型 ID 不写死——以 Omega 当前可用模型为准，通过配置文件切换（Haiku/Sonnet/Opus 为能力档位而非固定版本号）。 `[冻结折入 #3]`
**验收**：① 输出带「仅供中控参考」标记；② 不覆盖 L3 红卡；③ 不自动写入 FAQ；④ 不输出「包清关/包合规/包通过/保证中标」类承诺句。

### 7.7 直播复盘（散场自动）
产出：时长、总评论、最高在线、高频 Top10、L3 触发次数、L1/L2 命中率、未命中问题、疑似线索数、加微信数、预约/成交、有效话题、待入 FAQ、需禁话术。生成用 Sonnet 档位模型（离线，具体 ID 走配置），推送复用 Omega Telegram。
**验收**：① 散场 5 分钟内生成；② 高频统计准确；③ unknown 可导出给 Lei 审核；④ 直接更新 FAQ 待审核队列。

### 7.8 实时演讲红线监听（Speaker Redline Monitor）`[v1.3 扩展：S1/S2/S3 分级]`

**7.8.1 定位** — 独立并行的 P0 合规模块，不是评论采集的替代。监听对象只有一个：**主播本人直播中实际说出口的话**。不碰任何平台接口/抓包，ToS 零风险。目标不是「事前阻止开口」（语音说出后才能识别，物理上做不到），而是：说出高风险承诺后 ~1s 内报警 → 主播当场 walk back → 记录进复盘。法律暴露源头不是观众问什么，是主播答什么——本模块盯后者。**因为最便宜（自己的麦、本地 ASR、零 ToS）且守着最重的责任，它可能是全系统最先跑起来的模块。**

**7.8.2 与评论 Copilot 的关系** — 两条链并行、互不依赖。评论采集/抓包/OCR/人工输入全废时，本模块照常独立工作。

**7.8.3 监听源**（优先级）：① 主播麦克风本地音频流（V1 首选）② OBS/直播伴侣输出音轨 ③ 系统混音人声轨 ④ 录播文件离线复盘。要求：只采主播本人语音；不采观众私信/无关系统音；本地处理+本地存档；**只存命中红线片段+上下文窗口，不默认存全场音频**。

**7.8.4 工作流**：主播说话 → 本地流式 ASR → 文本清洗 → 规则匹配 → embedding/意图兜底 → 报警 → walk back → 写复盘。（不进 LLM 热路径）STT 引擎/模型走配置，不写死。

**7.8.5 红线词表来源**（继承+扩展，**新增词须 Lei 审核**）：演讲红线清单 v1.0 + L3 红线触发清单 + FAQ `forbidden_claims` + 复盘新增危险表达。种子词：包过 / 包清关 / 包 FDA / 保证过 / 保证中标 / 少报关税 / 低报货值 / 我们负责全部进口责任 / VOSB 一定能拿政府单 / 税可以这样避 / 海关不会查 / 出问题我们全赔 等。

**7.8.6 风险分级（本版核心改进）**

| 级 | 定义 | 示例 | 处理 |
| --- | --- | --- | --- |
| **S1 轻微** | 不够严谨，未成明确承诺 | 「这个一般没问题」「通常都能做」 | 中控黄灯：建议补边界句 |
| **S2 危险** | 构成承诺/保证/包办/规避 | 「我们包清关」「FDA 包过」「关税可以少报」 | 红卡 + 耳返「立即纠偏」+ walk back |
| **S3 严重** | 可能违法/规避监管/虚假承诺/政采误导 | 「帮你低报」「绕过 FDA」「保证店铺通过」「VOSB 保证拿合同」 | 强红卡 + 耳返 + 记时间戳 + 复盘列「必须纠正」+ **该片段禁止二次剪辑发布** |

**7.8.7 报警方式**：A 中控屏（默认，显示命中词/S 级/walk back 话术/时间戳/是否入复盘）；B 耳返/音频（可选，极短提示「纠偏/不要承诺/补边界」，不打断节奏）。V1 先做 A，耳返不阻断主模块验收。

**7.8.8 延迟目标**：ASR 转写 P95<800ms · 检测 P95<200ms · 显示 P95<200ms · **端到端 P95<1.2s**。

**7.8.9 Walk-back 机制** `[话术须过 Lei Gate]` — 报警须附可立即照读的纠偏句。**以下为草稿模板，必须经 Lei 审核过 Gate 才能作为自动建议话术上线——AI 写的纠偏句若把合规边界说歪，本身就是实时播出的新责任面。** 分类草稿：
- IOR/清关：「IOR 和清关责任涉及主体、产品、文件和进口责任边界，我们不能在直播间说包清关或包进口，具体要看你的产品和主体安排。」
- FDA：「FDA 要看产品类别、成分、标签、用途和进口文件，我们不能承诺包过，只能协助判断路径和风险点。」
- 政采/VOSB：「VOSB 是美国退伍军人企业资质，能增强主体可信度，但不能保证拿政府合同，也不替代产品、价格、交付和合规要求。」
- TikTok 店铺：「店铺申请要看主体、资料、类目和平台审核结果，我们协助准备和路径判断，但不能保证一定通过。」

**7.8.10 数据结构**：新增 `speaker_redline_events(event_id, session_id, timestamp, raw_transcript, normalized_text, matched_phrase, risk_level, category, suggested_walkback, alert_channel, operator_action, speaker_corrected, correction_text, include_in_recap, notes)`。

**7.8.11 复盘输出** — 复盘新增「主播红线表达监控」节：命中次数、S1/S2/S3 分布、最高风险片段、是否及时纠偏、下次必禁词、待入 `forbidden_claims`、禁剪片段、下场提醒清单。

**7.8.12 验收** `[修正：召回 95%→98%；ASR 口径修正]`
- **功能**：连续监听 ≥2h；识别普通话+中英夹杂；命中后中控可见；S2/S3 必给 walk back；事件写复盘；不依赖评论采集。
- **性能**：端到端 P95<1.2s；**S2/S3 红线召回 ≥98%（不是 95%）**，S1 ≥90%；**S3 漏报=致命失败，逐条排查，不按 5% 容忍**；连续 ≥2h 不中断。
- **ASR 口径**：唯一硬指标是**红线短语召回率**，容忍其余转写噪声（整体可读率/CER 不作门槛）。
- **合规**：不替主播发言；不自动上播；不存无关全场音频；未审 walk back 不写入 FAQ；不覆盖 L3 评论红卡；不抓平台评论；**所有红线词表 + walk back 话术须 Lei 审核**。

**7.8.13 Go / No-Go** — Go：ASR 稳定监听 + **S2/S3 召回 ≥98%** + 报警不破坏节奏 + 中控愿用 + 复盘可见危险表达。No-Go：误报泛滥被忽略 / 延迟>2s / ASR 抗噪差 / 频繁把安全表达误判成 S3 / 主播无法及时纠偏 → **降级离线复盘模式**（录播 → ASR → 红线扫描 → 「主播危险表达复盘」）。即使实时失败，离线红线复盘仍作 V1 保留能力。

## 8. 成功指标

**P0**：Ingestion 是否跑通（或降级可用）· 红线召回 ≥98% · FAQ top-1 ≥85% · 中控是否真的愿意用。
**P1**：复盘是否省时 · 未命中是否能沉淀 FAQ · 高价值线索是否被记录 · 主播危险表达是否减少。
**不作 V1 指标**：成交率 / GMV / 剪辑效率 / 全平台覆盖。

## 10. Go / No-Go Gate

**Gate 1 · Ingestion** — Go：评论稳定进 + 延迟可接受 + 可重连 + 风险可接受。No-Go：抓不到/不稳/风险不可接受 → 转人工副屏输入，不阻断 FAQ/红线/复盘开发。

**Gate 2 · 红线** — Go：召回 ≥98% + 无明显危险漏判 + 中控看懂红卡。No-Go：IOR/FDA/清关/税务类漏判严重 / AI 生成承诺句 / UI 挡不住主播误说 → 暂停长尾生成，只留红线规则 + 人工判断。

**Gate 3 · 真实直播** — Go：中控愿继续用 + 复盘有价值 + 命中率可迭代提升 + 主播危险表达减少。No-Go：中控觉得碍事/卡片太慢/命中不准/打断节奏 → 降级为散场复盘工具，不做实时 Copilot。

## 12. 权限与安全

① 评论日志默认本地保存；② 不抓他人直播间；③ 不存用户敏感信息，用户名可 hash；④ 高风险合规答案必须人工审核；⑤ LLM 输出不得自动进标准话术库；⑥ 标准答案保留审核人+时间；⑦ 删除「保证/包过/包清关/包合规/包中标」承诺表达；⑧ 主播语音监听仅用于本场合规提醒与复盘，不默认保存全场音频，只存红线命中片段+上下文；红线词表与 walk-back 话术均须 Lei 审核。
